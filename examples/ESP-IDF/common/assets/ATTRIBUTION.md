| Part | Author | Licence |

| Model | PixelMannen | [CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/legalcode) |
| Rigging & Animation | tomkranis | [CC-BY 4.0](https://creativecommons.org/licenses/by/4.0/legalcode) |
| Conversion to glTF | @AsoboStudio and @scurest | [CC-BY 4.0](https://creativecommons.org/licenses/by/4.0/legalcode) |

`../fox.a3d` is generated from this file and inherits the same terms:

```bash
python3 ../../../tools/a3d_export.py --gltf third_party/Fox.glb -o fox.a3d
```

### Why it is here

Every fixture before this one was generated by `a3d_export.py`, so every fixture
reflected the same assumptions the importer was built on. A real asset that
nobody on this project authored is the only thing that tests those assumptions -
and it immediately found one: **Fox has no NORMAL attribute**, which the runtime
silently downgraded to unlit. The importer now generates normals.

The user has said these are for local testing only and will not be published,

```bash
python3 ../../../tools/a3d_export.py --gltf <file>.glb -o <name>.a3d --max-texture 256
```

`brainstem` is the demo default of the three-way switch because it is the
heaviest fixture **and** the only high-poly one whose scratch buffer fits in
internal RAM: 61,666 triangles split across 59 parts leaves the largest at 6,614,
so scratch is 78 KB. `shark` carries the same triangles in one part and would
need 600 KB.

The source `.glb` files are not committed; the table says where each came from.

### What the dragon found before it was replaced

`tarisland_dragon_high_poly` (CC-BY 4.0, Dr A via Sketchfab, BabylonJS/Assets)
was the fixture before this one, and two importer defects came out of it:

**Materials with no `pbrMetallicRoughness` at all.** Its diffuse colour and
texture live in `KHR_materials_pbrSpecularGlossiness`, which the importer never
read, so the model rendered untextured and flat white without complaint. Fixed,
with a warning when the fallback is taken.

**Animation is most of the container.** Its 156-bone rig over 27 clips came to
16.7 MB of `ANIM` against 652 KB of `MESH` - not because keys are unquantized
(they are int16/uint16 and always were) but because there are 1.86 million of
them. Keyframe reduction now brings that to 3.4 MB.

## Pokemon fixtures

`pikachu` `charizard` `gengar` `mewtwo`, from
https://github.com/Pokemon-3D-api/assets - an unofficial fan project. These are
**Nintendo / The Pokemon Company** characters and the models are game rips. Local
testing only, at the user's direction; they must not be published.

| fixture | tri | parts | bones | clips |
|---|---|---|---|---|
| `pikachu` | 4,556 | 5 | 45 | 1 (Impactrueno) |
| `charizard` | 6,218 | 5 | 72 | 1 |
| `gengar` | 4,308 | 2 | 31 | **0** |
| `mewtwo` | 9,691 | 4 | 88 | **71** |

They arrive Draco-compressed with WebP textures, which the importer does not
read. Decompress first, then convert:

```bash
npx --yes @gltf-transform/cli copy 25.glb 25_raw.glb    # decodes Draco
python3 ../../../tools/a3d_export.py --gltf 25_raw.glb -o pikachu.a3d --max-texture 256
```

### What they found

**Textures named through an extension were invisible.** `EXT_texture_webp` puts
the image index in `texture.extensions`, not `texture.source`. The importer read
only `source`, found nothing, and produced an untextured model without
complaint - the third defect of exactly this shape, after the Fox's missing
NORMAL and the dragon's missing `pbrMetallicRoughness`. Pillow decodes WebP
already; the only thing missing was looking in the right place.

**A camera framed from one pose loses a model that moves.** Pikachu's clip jumps
clear of the bind pose, and the panel showed an empty screen for a quarter of
every loop - 5 of 19 measured seconds had zero draw calls. The demo now samples
up to 16 poses per clip at startup and unions the bounds; empty seconds went to
0 of 19 and the frame rate steadied from a 17-89 swing to 26-30.

**BrainStem** (61,666 triangles, 59 primitives) is licensed under the **Poser
EULA**, not a Creative Commons licence. It is used as a local fixture at the
user's direction (see above) and its `.a3d` must not be published. That EULA restricts redistributing the mesh
connectivity, which is exactly what a converted `.a3d` contains. Convert it
locally if you want the measurement; do not commit the result.

**RecursiveSkeletons** (CC-BY 4.0, 84 skeletons, 840 animation channels) is
blocked by the format, not the licence: `SkinEntry` already carries a
`skeleton_index`, but the `SKEL` chunk is a single flat bone array and the
runtime ignores that index. The exporter refuses rather than writing a file that
would render wrong. It is the acceptance test for multi-skeleton support.
